## 1. Зачем нужен этот фронтенд

Это клиентская часть учебного проекта по RBAC (Role-Based Access Control). Пользователь заходит в систему, после чего может:

- смотреть и редактировать **матрицу прав** (какая роль что может делать);
- смотреть список **пользователей** с поиском и пагинацией;
- открыть **карточку пользователя** с ролями и эффективными правами;
- читать **журнал доступа** (кто что пытался сделать и разрешили или нет).

Фронтенд **не работает сам по себе** — ему нужен запущенный Django-бэкенд на `http://localhost:8000`. Mock-данных нет, всё тянется с API.

## 4. Страницы приложения

### 4.1. `login.html` — вход

- Форма: логин + пароль.
- При отправке вызывается `auth.login()`.
- Если уже есть токен в `localStorage` — сразу перекидывает на `matrix.html`.
- При ошибке показывает текст под формой (красным).

### 4.2. `matrix.html` — матрица прав

Главная рабочая страница после входа.

- Таблица: **строки** — права, **столбцы** — роли (Пользователь, Менеджер, Аудитор, Администратор).
- В ячейках три состояния:
  - **✓** — явно разрешено (`allow`);
  - **✕** — явно запрещено (`deny`);
  - **🕒 насл.** — наследуется от родительской роли (только показ, в БД не пишется).
- Клик по ячейке переключает: пусто → allow → deny → пусто.
- Кнопка **«Сохранить»** активна только если что-то изменилось. Отправляет **только изменённые** ячейки.

### 4.3. `users.html` — пользователи

- Загрузка списка через `GET /api/admin/users/`.
- Поле поиска по логину и ФИО (фильтрация на клиенте).
- Таблица: ФИО, логин, роли, статус.
- Клик по строке открывает карточку `user.html#<id>`.
- Пагинация на клиенте (по 10 записей на страницу).
- Состояния: загрузка, пустой список, ошибка (в т.ч. 403 при отсутствии права `manage_roles`).

### 4.4. `user.html` — карточка пользователя

- Открывается по адресу `user.html#5` (число после `#` — id пользователя).
- **Свой профиль:** `GET /api/admin/users/:id/` с fallback на `GET /api/auth/me/`.
- **Чужой профиль:** `GET /api/admin/users/:id/` — логин, статус, роли, эффективные права.
- Для доступа к чужим карточкам нужно право `manage_roles`.

### 4.5. `audit.html` — журнал доступа

- Таблица: время, пользователь, действие, результат (разрешено / отказано).
- Фильтр по результату: любой / разрешено / отказано.
- Пагинация на клиенте (бэкенд отдаёт весь список, фронт режет по 10 записей).

### 4.6. Общая шапка

На всех страницах кроме логина:

- логотип RBAC;
- ссылки: Матрица, Пользователи, Журнал;
- кнопка **«Выйти»** — очищает `localStorage` и ведёт на `login.html`.

Активный пункт меню подсвечивается через атрибут `data-page` на `<body>`.

## 5. JavaScript-модули

### 5.1. `auth.js` — авторизация

**Ключ в localStorage:** `rbac_session`

После успешного входа там лежит объект:

```json
{
  "token": "abc123...",
  "username": "admin",
  "fullName": "admin",
  "userId": 1
}
```

| Функция | Что делает |
|---------|------------|
| `getSession()` | читает объект из localStorage |
| `getToken()` | достаёт только token |
| `requireAuth()` | если нет токена — редирект на login.html |
| `redirectIfAuthenticated()` | если уже залогинен — на matrix.html |
| `login(username, password)` | POST `/auth/login/`, затем GET `/auth/me/` |
| `logout()` | удаляет сессию, редирект на login |

Каждый запрос в `api.js` добавляет заголовок:

```
Authorization: Token <ваш_токен>
```

### 5.2. `api.js` — слой API

Базовый URL: `http://localhost:8000/api`

Общая обёртка `request(method, path, body)` над `fetch`. При ошибке бросает `Error` с текстом от сервера.

| Метод | HTTP | Путь | Описание |
|-------|------|------|----------|
| `getMatrixView()` | GET | `/admin/matrix/` | загрузка матрицы |
| `saveMatrixView(...)` | POST | `/admin/matrix/` | сохранение изменений |
| `getAuditLog(params)` | GET | `/admin/audit-logs/` | журнал + клиентская пагинация |
| `getUsers(params)` | GET | `/admin/users/` | список + поиск + пагинация |
| `getUser(id)` | GET | `/admin/users/:id/` | карточка + эффективные права |
| `getMe()` | GET | `/auth/me/` | свой профиль + права |
| `getMyPermissions()` | GET | `/auth/me/` | только права |

### 5.3. `api-adapters.js` — адаптеры данных

Бэкенд и UI говорят на разных «языках». Этот файл переводит JSON туда-обратно.

**Каталог ролей и прав** (`ROLES_CATALOG`, `PERMISSIONS_CATALOG`) — из `backend/rbac_auth/fixtures/init_data.json`, потому что отдельных эндпоинтов справочников пока нет.

| Функция | Назначение |
|---------|------------|
| `matrixFromApi(apiRules)` | плоский список правил → таблица UI + наследование 🕒 |
| `matrixChangesToApi(...)` | diff «было/стало» → `{ changes: [...] }` для POST |
| `auditFromApi(rows)` | поля журнала к единому виду |
| `usersFromApi(rows)` | список/карточка пользователя: логин, ФИО, роли, статус |
| `effectiveFromMe(me)` | `{ view_records: "allow", ... }` → список для карточки |
| `meToUser(me)` | `/auth/me/` → формат карточки пользователя |

### 5.4. `matrix.js` — логика матрицы

Хранит в памяти `permissions`, `roles`, `bindings`, `savedBindings`.

Кнопка «Сохранить» сравнивает только **allow/deny** (наследование в сравнение не входит).

### 5.5. `utils.js` — утилиты

- `$()` — alias для `document.querySelector`;
- `renderLoading`, `renderEmpty`, `renderError` — состояния контейнера;
- `formatTime` — время для журнала;
- `statusLabel` — перевод статуса на русский;
- `setActiveNav` — подсветка активного пункта меню.

### 5.6. `layout.js`

`initAppShell()` на каждой защищённой странице:

1. проверяет авторизацию;
2. вешает обработчик на «Выйти»;
3. подсвечивает текущую страницу в меню.

## 6. Как фронт общается с бэкендом

### 6.1. Вход

```
POST /api/auth/login/
Body: { "username": "...", "password": "..." }

Ответ 200: { "token": "..." }
Ответ 400: { "error": "Неверный логин или пароль" }
Ответ 403: { "error": "Ваш аккаунт заблокирован..." }
```

Затем фронт делает `GET /api/auth/me/` и сохраняет `userId` в сессию.

### 6.2. Матрица

```
GET  /api/admin/matrix/
POST /api/admin/matrix/
Body: { "changes": [{ "role_id": 2, "permission_id": 3, "grant": "allow" }] }
```

`grant: "none"` — убрать явное правило (вернуться к наследованию).

### 6.3. Журнал

```
GET /api/admin/audit-logs/?result=deny
GET /api/admin/audit-logs/?user_id=1
GET /api/admin/audit-logs/?date_from=2026-01-01&date_to=2026-06-01
```

### 6.4. Пользователи

**Список:**

```
GET /api/admin/users/
```

Ответ:

```json
[
  {
    "id": 1,
    "username": "admin",
    "is_blocked": false,
    "roles": ["Администратор"]
  }
]
```

**Карточка:**

```
GET /api/admin/users/5/
```

Ответ:

```json
{
  "id": 5,
  "username": "vasya",
  "is_blocked": false,
  "roles": ["Менеджер"],
  "effective_permissions": {
    "view_records": "allow",
    "delete_records": "deny"
  }
}
```

Для обоих эндпоинтов на бэкенде требуется право `manage_roles`.

## 7. Роли и права (справочник на фронте)

Пока бэкенд не отдаёт справочники отдельными запросами, на фронте зашиты данные из `init_data.json`:

**Роли:**

| ID | Название | Родитель |
|----|----------|----------|
| 1 | Пользователь | — |
| 2 | Менеджер | Пользователь |
| 3 | Аудитор | — |
| 4 | Администратор | — |

**Права:**

| ID | Codename | Название в UI |
|----|----------|---------------|
| 1 | view_records | Просмотр записей |
| 2 | create_records | Создание записей |
| 3 | delete_records | Удаление записей |
| 4 | view_audit | Просмотр журнала логов |
| 5 | export_audit | Экспорт логов |
| 6 | manage_roles | Управление ролями |
| 7 | view_matrix | Просмотр матрицы прав |
| 8 | save_matrix | Сохранение матрицы |

## 8. Наследование прав (как показывается 🕒)

Бэкенд хранит только **явные** правила (allow/deny). Наследование считается на фронте:

1. Берём роль с родителем (Менеджер → Пользователь).
2. Если у Менеджера нет своего правила, но у Пользователя стоит **allow** — показываем 🕒 «насл.».
3. При клике наследование не сохраняется в БД — пользователь задаёт allow/deny или сбрасывает в none.

## 10. Как запустить локально

### Фронтенд

Из папки `frontend/`:

```bash
npx serve . -p 3456
```

Открыть: http://localhost:3456/login.html

Нужен локальный сервер (не `file://`) — JS-модули требуют HTTP.

### Бэкенд

Ветка `development`, папка `backend/`:

```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install django djangorestframework django-cors-headers psycopg2-binary python-dotenv
python manage.py migrate
python manage.py loaddata init_data.json
python manage.py createsuperuser
python manage.py runserver
```

Пользователю нужно назначить роль **Администратор** (через Django admin), иначе матрица, журнал и список пользователей вернут 403.

## 11. Типичные ошибки

| Сообщение / поведение | Причина |
|-----------------------|---------|
| «Ошибка 403» на матрице | нет `view_matrix` / `save_matrix` |
| «Ошибка 403» на пользователях | нет `manage_roles` |
| «Failed to fetch» | бэкенд не запущен |
| «Сервер не вернул токен» | не настроен `rest_framework.authtoken` |
| Пустой журнал | ещё не было обращений к защищённым эндпоинтам |
