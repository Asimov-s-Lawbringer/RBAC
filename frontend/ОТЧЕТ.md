### 4.3. Архитектурные решения

**Почему без React/Vue:** для учебного проекта проще объяснить чистый JS. Нет сборки, минимум зависимостей.

**Почему отдельный `api-adapters.js`:** бэкенд отдаёт данные в одном формате, UI нужен другой. При смене API правки в основном там.

**Почему каталог ролей на фронте:** бэкенд не отдаёт `/admin/roles/`. Данные из fixture — ids совпадают с БД.

**Почему наследование в UI:** в БД только явные allow/deny. 🕒 считается на фронте для наглядности.

**Почему пагинация на клиенте:** бэкенд отдаёт полные списки. Для учебного объёма данных этого достаточно.

## 5. Сложности и как решал

### 5.1. Бэкенд не совпадал с первоначальным контрактом

**Проблема:** другие URL и формат JSON: Token вместо session, POST вместо PUT, плоский список вместо сводной таблицы.

**Решение:** прочитал `views.py` и `urls.py`, переписал `api.js`, `auth.js`, `api-adapters.js`.

### 5.2. API не в той ветке

**Проблема:** в `development` сначала не было views.

**Решение:** дождались мержа `feat/back-models-filling` → `development`. Фронт был готов к формату API заранее.

### 5.3. Эндпоинт пользователей появился позже

**Проблема:** `users.html` была готова, но API не было — показывалась заглушка.

**Решение:** после появления `GET /admin/users/` и `GET /admin/users/:id/` подключил реальные запросы, добавил `usersFromApi`, убрал заглушку.

### 5.4. CORS

**Проблема:** фронт на порту 3456, бэкенд на 8000 — браузер блокировал запросы.

**Решение:** на бэкенде подключён `django-cors-headers`, `CORS_ALLOW_ALL_ORIGINS = True`.

### 5.5. Разные форматы прав в API

**Проблема:** `/auth/me/` отдаёт `permissions`, а `/admin/users/:id/` — `effective_permissions`.

**Решение:** `effectiveFromMe()` обрабатывает оба варианта.

## 6. Взаимодействие с бэкендом

Для интеграции разобрался в серверной части:

- модели: `CustomUser`, `CustomRole`, `AppPermission`, `RolePermission`, `AuditLog`;
- права проверяются `HasMatrixPermission` — при запросе пишется запись в журнал;
- эффективные права — `calculate_effective_permissions()` с цепочкой родителей;
- список пользователей требует право `manage_roles`;
- тестовые данные — `fixtures/init_data.json`.
